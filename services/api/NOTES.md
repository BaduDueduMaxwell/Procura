# Buyer intake rationale

Procura now treats buyer intake as a persisted aggregate separate from the existing supplier-decision conversation so text and spreadsheet rows can be corrected without changing proven quotation logic. LangGraph fixes validation order and owns buyer-interrupt/resume state; LangChain supplies typed tools and the optional Gemini structured-output adapter, while pure Python validators remain the authority for repeatable checks. The hosted interpreter now returns procurement intent inside its typed semantic result instead of being blocked by a fixed term list; the local provider accepts unseen catalogue names only when clinical structure is present. SQLAlchemy stores the user-facing aggregate with tenant checks, idempotency keys, and optimistic versions, and the graph checkpointer stores execution position so refreshes and process restarts do not erase progress. Intake HTTP handlers now live in `app/api/intakes.py`; parsing, interpretation, validation, orchestration, persistence, observability, and review creation remain separate concerns.

The likely first failure point is very large or unusually formatted workbooks: this version bounds archive expansion, file size, worksheets, and row count, but does not implement every legacy Excel encoding or merged-header convention. The no-key interpreter cannot understand every possible sentence semantically, so it requires clinical structure or catalogue evidence and fails closed when neither exists; hosted Gemini performs the semantic intent decision. Gate tests cover API ownership, parsing, correction, suggestion decisions, concurrency, refresh/resume, idempotent submission, varied out-of-scope input, unseen medicine names, and critical-review creation. The final local run passed Ruff, the configured mypy gate across 27 backend modules, 88 backend tests, and 29 frontend tests; both deterministic evaluation lanes passed at 100%. Roll back with `git revert <buyer-intake-commit>` and redeploy both services; the additive `procurement_intakes` table can remain unused without affecting earlier code.

The Ghana brand update replaces three unsupported hard-coded aliases with a versioned catalogue of 10 active Ghana FDA product records across multiple manufacturers. Exact brand lookup is deterministic; the buyer sees the registered active ingredient, variant, manufacturer, expiry-backed source record, and must accept or reject before the generic name changes. This approach avoids a live registry dependency and prevents the model from inventing brand relationships, while preserving the original request and decision actor for audit. The likely first failure point is source freshness after a registration expires or a new brand appears, so expired records stop matching and the curated file must be refreshed from the official register. Final verification passed 96 backend tests, 30 frontend tests, 15/15 supplier-decision evaluations, 25/25 buyer-intake evaluations, lint, type checks, the Next.js production build, both container builds, and mobile browser QA at 375×812. Roll back with `git revert <ghana-brand-commit>` and redeploy the API and web services; no database migration is involved.
