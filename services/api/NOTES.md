# Buyer intake rationale

Procura now treats buyer intake as a persisted aggregate separate from the existing supplier-decision conversation so text and spreadsheet rows can be corrected without changing proven quotation logic. LangGraph fixes validation order and owns buyer-interrupt/resume state; LangChain supplies typed tools and the optional Gemini structured-output adapter, while pure Python validators remain the authority for repeatable checks. SQLAlchemy stores the user-facing aggregate with tenant checks, idempotency keys, and optimistic versions, and the graph checkpointer stores execution position so refreshes and process restarts do not erase progress. Final confirmation runs the repository-backed supplier gates and creates one specific critical review only when no quotation is eligible. This composition was selected over extending the original conversation service because spreadsheet batches, row versions, correction decisions, and confirmation have a different lifecycle.

The likely first failure point is very large or unusually formatted workbooks: this version bounds archive expansion, file size, worksheets, and row count, but does not implement every legacy Excel encoding or merged-header convention. Gate tests cover API ownership, parsing, correction, suggestion decisions, concurrency, refresh/resume, idempotent submission, and critical-review creation. The final local run passed Ruff, mypy across 25 backend modules, 83 backend tests, and 29 frontend tests. Both deterministic evaluation lanes passed: supplier decision 15/15 and buyer intake 19/19 at a 90% threshold. Roll back with `git revert <buyer-intake-commit>` and redeploy both services; the additive `procurement_intakes` table can remain unused without affecting earlier code.
